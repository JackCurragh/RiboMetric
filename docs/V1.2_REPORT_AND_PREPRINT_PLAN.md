## Part 1 — What RiboMetric v1.2 Supports

### 1.1 Overview

RiboMetric is a Python command-line tool for **comprehensive quality assessment of
ribosome profiling (Ribo-Seq) datasets**. Given a coordinate-sorted *transcriptomic*
BAM and a transcript annotation, it computes a broad panel of QC metrics, renders an
interactive HTML report (plus PDF/JSON/CSV/TSV outputs), and can gate a pipeline on
pass/warn/fail thresholds. It is MIT-licensed, on PyPI (`pip install RiboMetric`), and
ships a multi-arch Docker image (`ghcr.io/jackcurragh/ribometric`).

The guiding philosophy (from `docs/METRICS.md`): *provide objective measurements
without labelling datasets "good" or "bad"* — communities set their own thresholds.

### 1.2 Architecture & subcommands

| Subcommand | Purpose |
|---|---|
| `prepare` | Convert a GFF3/GTF annotation into a compact TSV (vectorised numpy/pandas, multi-threaded) used by `run`. |
| `run` | Parse a BAM with `oxbow` (Rust-backed, zero-copy) + `pysam`, compute metrics, write outputs. |
| `evaluate` | Score a prior result (JSON or metrics-table CSV) against YAML thresholds; exits **0/1/2 = PASS/WARN/FAIL** for Nextflow/Snakemake gating. |
| `view` | Interactive terminal UI (TUI) to navigate a result JSON without a browser. |

Both `RiboMetric` and lowercase `ribometric` entry points work. ~9,000 LOC across
20 modules; comprehensive pytest suite (run via `pixi run test`).

Key correctness choices baked into the engine:
- Read length derived from **CIGAR consumed-bases** (M/=/X/I), robust to soft-clipping.
- **Multimapper-aware**: frame-sensitive metrics default to uniquely-mapped reads
  (MAPQ=255) for STAR transcriptome BAMs (`--multimap-filter unique_only|none`).
- **Deduplication-weighted**: collapsed reads carry a `count` column used as weights
  throughout, avoiding double-counting.
- Robust to **sequence-less BAMs** (`--skip-sequence-metrics`).

### 1.3 Metric panel

**Default metrics (no flags required):**

- **Read-length distribution** — IQR, coefficient of variation, max proportion,
  **bimodality coefficient**.
- **Terminal nucleotide (ligation) bias** — 5′ and 3′ KL-divergence scores (+ raw bits)
  and max-absolute deviation.
- **3-nt periodicity** — `periodicity_dominance` (global shared dominant frame) and
  `periodicity_information` (Shannon information content).
- **Metagene uniformity** — entropy over the codon-binned start-codon window.
- **CDS coverage & regional distribution** — `CDS_coverage`, region ratios and
  proportions (5′UTR / CDS / 3′UTR).
- **Alignment quality** *(new in v1.2)* — `duplicate_rate`, `multimapper_rate`,
  `soft_clip_rate_5prime`, plus flagstat totals in `results["alignment_stats"]`.
- **Di-some detection** *(new in v1.2)* — `disome_proportion` (50–70 nt window) and
  read-length bimodality (promoted to default).
- **Codon-level translation** *(new in v1.2)* — `stop_codon_readthrough_ratio`,
  `start_codon_enrichment_ratio` (proxy for harringtonine/LTM initiation libraries).
- **Recommended read lengths** *(new)* — which lengths carry clean 3-nt periodicity,
  their P-site offsets, and the library fraction they represent
  (`recommended_read_proportion`; tune with `--min-periodicity`).
- **Gene-body coverage ramp** *(new)* — A-site density across relative CDS position
  (0–100%); `five_prime_ramp_ratio`, `three_prime_drop_ratio`.
- **Library complexity / saturation** *(new)* — analytic rarefaction curve
  (`marginal_position_discovery_rate`, `complexity_distinct_positions`) — no random
  subsampling.
- **Library-type classification** *(new)* — heuristic `elongation` / `initiation` /
  `low_quality` label with recorded supporting evidence.
- **FLOSS read-length heterogeneity** *(new)* — fraction of transcripts with aberrant
  footprint-length profiles (`floss_median`, `floss_aberrant_transcript_fraction`);
  a library-homogeneity QC.

**FASTA-dependent (auto when `--fasta` supplied):**
- **A-site codon dwell-times / pause sites** *(new)* — per-codon occupancy vs codon
  abundance; `codon_dwell_cv`, `codon_dwell_p90_p10`, `proline_dwell`, `cga_dwell`.

**Optional (`--enable-metric` / `--enable-optional-metrics`):**
- `rust_mean_kl_divergence` — RUST metagene KL divergence (O'Connor et al. 2016),
  requires `--fasta`.
- Alternative periodicity: autocorrelation, Fourier, Trips-Viz.
- Alternative uniformity: Theil index, Gini index, autocorrelation.
- Read-length normality test.

### 1.4 Outputs

- **Interactive HTML** (Jinja2 + Plotly) with executive summary and searchable metrics.
- **PDF** (via `RiboMetric[pdf]` extra).
- **JSON** machine-readable result (full nested data incl. `rust`, `alignment_stats`).
- **Tabular**: `--summary-tsv`, `--qc-status`, `--comparison-csv` (wide, multi-sample),
  `--metrics-table` (read-length breakdowns); `--improved-outputs` bundles them.
- **Interactive TUI** via `view`.
- Dedicated plots: codon dwell, FLOSS, recommended read lengths, gene-body coverage,
  library complexity, read-frame distributions/triangle, metagene profile/heatmap,
  terminal-bias, nucleotide composition, mRNA distribution.

### 1.5 Metric directionality & gating

Most metrics are normalised **higher-is-better** (`periodicity_dominance`,
`uniformity_entropy`, `prop_reads_CDS`). A few are **lower-is-better**
(`duplicate_rate`, `multimapper_rate`, `soft_clip_rate_5prime`, `disome_proportion`,
`stop_codon_readthrough_ratio`, raw terminal-bias). `evaluate` now honours direction
per-metric (overridable via `direction: lower|higher` in the thresholds YAML) — a fix
in v1.2 so a high duplicate rate fails rather than passes.

### 1.6 What changed since v1.1 (correctness highlights)

The v1.2 line included several substantive correctness fixes worth flagging in a paper:
- **GFF coordinate off-by-one** — exon lengths were `end − start` despite GFF3 being
  1-based inclusive, shifting `cds_start` and scrambling reading frame/periodicity for
  multi-exon transcripts. *Annotation TSVs from older `prepare` should be regenerated.*
- **Terminal-bias 3′ background** — 5′/3′ ligation backgrounds were identical (the
  `five_prime` flag was ignored).
- **RUST KL divergence** — replaced a non-standard per-term `abs()` with a standard KL
  over the observed support.
- **`--offset-global`** previously silently ignored; **bare `RiboMetric`** crashed
  instead of printing help.
- Spectral metrics (Fourier/Theil/Gini) now default to all observed read lengths rather
  than a hardcoded human 25–35 nt window.

## Part 2 — Pre-print Plan

### 2.1 Positioning & gap

A JOSS-style `paper.md` already exists but is thin for a methods pre-print. The
positioning gap to claim: **no single tool delivers the full QC spectrum — raw read
properties → periodicity → regional distribution → translation-pathology signals
(disome, readthrough, dwell-times) → automated pass/fail gating — as a
pipeline-native, multimapper-aware Python package.** Existing tools (RiboProfiling,
riboWaltz, RiboTaper, plus newer ones) each cover a slice.

**Two viable venues — decide early, they shape scope:**
- **JOSS** (software paper): minimal narrative, the existing `paper.md` is ~80% there.
  Fast, but low on biological validation / benchmarking.
- **Bioinformatics / NAR / GigaScience / *Genome Biology* methods**: requires
  benchmarking against real datasets, comparison to existing tools, and demonstration
  that the metrics discriminate good vs bad libraries. Higher impact; more work.

A pre-print (bioRxiv) can precede either. Recommendation below assumes the
**Bioinformatics/methods route** with a bioRxiv pre-print first.

### 2.2 Proposed manuscript structure

1. **Abstract** — comprehensive, pipeline-native, multimapper-aware QC; gating.
2. **Introduction** — Ribo-Seq artefacts; why QC matters for TE/ORF/codon analyses;
   fragmentation of existing QC tooling.
3. **Implementation** — three subcommands; oxbow/pysam engine; CIGAR-based length;
   dedup weighting; multimapper handling; metric tiers; outputs.
4. **The metric panel** — group the metrics into themes with a figure per theme:
   (a) read/alignment integrity, (b) periodicity & frame, (c) regional/coverage,
   (d) translation-state signals (disome, readthrough, start enrichment, dwell, RUST),
   (e) library-level QC (complexity, FLOSS, recommended lengths, library-type).
5. **Benchmarking / validation** *(the key new work — see 2.3)*.
6. **Pipeline integration** — `evaluate` gating example in Nextflow; multi-sample
   comparison CSV; RiboSeq.Org / large-scale reprocessing angle.
7. **Discussion & availability**.

### 2.3 Benchmarking work needed (the gating item)

This is what separates a pre-print from the existing JOSS stub. Suggested experiments:

- **Discrimination**: run on a curated set of known-good vs known-degraded libraries
  (e.g. from RiboSeq.Org / GWIPS-viz reprocessed data you already have under
  `all-RiboSeq/`) and show metrics separate them (ROC / PCA of the metric vector).
- **Treatment detection**: show `start_codon_enrichment_ratio` flags
  harringtonine/LTM (initiation) libraries; `disome_proportion` flags disome-seq.
- **Concordance**: compare `periodicity_dominance` / P-site offsets to riboWaltz on the
  same samples; quantify the multimapper-filter effect (the 0.53→0.70 example).
- **Scalability**: runtime/memory vs library size; oxbow vs pysam-only baseline.
- **Reproducibility of fixes**: demonstrate the GFF off-by-one fix changes periodicity
  on multi-exon transcripts (before/after).
